# ADR-0007: 座位平面图与插座覆盖范围的数据模型

Status: implemented
Date: 2026-10-25
Related: REQ-M1-10、REQ-M1-09；TASK-017、TASK-018；[ADR-0003](2026-10-25-service-topology.md)

## 问题

组长在评审 base repo 的座位页时提出：座位应按真实相对位置显示在 2D 平面图上，并显示插座位置及其可用范围。原模型只有每个座位一个手工维护的 `hasPowerOutlet` 布尔值，既画不出平面图，也表达不了"可用范围"。需要决定座位与插座如何建模，以及"靠近插座"由谁说了算。

## 决定

- 自习室增加平面尺寸 `width`、`height`；座位增加坐标 `x`、`y`。坐标是**抽象网格单位**（左上角为原点，一格约一张桌子宽），不是米，不依赖实测图纸。
- 新增独立实体 `power_outlets`：位置、类型（`FIXED` 墙插 / `RAIL` 导轨）、覆盖半径 `range`（网格单位，欧氏距离，含边界）。
- 座位的 `hasPowerOutlet` 由读取时根据插座位置与半径**推导**（`seat-power.ts › withDerivedPower`），不再手工维护。数据库列保留一个发布周期以便回滚（expand/contract），下一发布删除。
- `GET /api/m1/rooms/:id/seats` 返回 `room{width,height}`、`seats[{x,y,hasPowerOutlet}]` 与完整的 `outlets[]`；`hasPower` 筛选只作用于座位，插座列表始终完整，前端才能画出全部覆盖圈。
- 坐标录入短期由种子数据提供（三间演示自习室），管理员在线编辑布局另开任务。

## 备选方案

| 方案 | 做法 | 为什么落选 |
|---|---|---|
| A. 只加座位坐标，插座标记仍手工维护 | 最省事 | "可用范围"没有数据来源，平面图上的圈只是装饰，与需求不符 |
| **B. 插座实体 + 半径，座位电源由位置推导（本方案）** | 见上 | 改一个插座全图联动；数据真实；代价是 REQ-M1-09 的验收标准改写为派生规则 |
| C. 插座实体 + 显式"覆盖座位列表" | 管理员逐个指定 | 更精确但录入成本高；可在 B 之上作为例外机制补充 |
| D. 位图 / CAD 底图 + 像素坐标 | 最逼真 | 没有图纸来源，维护成本高，手机端缩放复杂 |

## 后果

- 契约变更（`RoomDto`、`SeatDto` 新增字段，新 `PowerOutletDto`，响应新增 `outlets`），均为新增字段，现有消费方（web）无需改动即可编译。
- M2/M3 以后若需要房间信息，继续通过 M1 公开接口读取，不受影响。
- 任务拆为两个 MR：TASK-017 数据模型 + 接口 + 契约（本 ADR 所在 MR），TASK-018 前端 SVG 平面图。
- 覆盖判定是纯函数，变异测试可直接作用；破坏该函数时集成测试与 e2e 都必须变红。

## 验证

- `seat-power.spec.ts`：圆内、边界、圆外、多插座、不可变。
- `rooms.int-spec.ts`：接口返回坐标、推导出的电源标记与插座列表；`hasPower` 只筛座位。
- 种子重放后 LIB-301 有 10 个座位被覆盖（2 个墙插各 1 座 + 导轨 8 座），与 e2e 断言一致。
