# ADR-0012: M3 维修进度使用明确操作接口

Status: implemented
Date: 2026-11-12
Related: TASK-032、REQ-M3-03、[ADR-0011](2026-11-12-m3-master-data-validation.md)

## 问题

工单派单后需要允许维修人员开始维修、标记完工，并让相关人员追溯事件。直接开放任意目标状态会让后续 SLA、验收和跨模块写回流程在尚未实现时被提前调用。

## 决定

提供 `start` 与 `complete` 两个操作接口，分别请求进入 `IN_PROGRESS` 和 `DONE`；仅当前被指派的维修人员可操作。两个接口继续通过现有状态机判断迁移，在同一数据库事务中条件更新工单并追加事件。事件历史仅供上报人、当前被指派人和管理员读取，按时间与事件 id 稳定排序。`DONE` 表示维修完成、待验收，本任务不写回 M1 座位状态。

## 备选方案

- 通用状态修改接口：代码较少，但会把 `ESCALATED`、`ACCEPTED` 等尚未完成的业务流程暴露给调用方，难以执行各状态专有的权限与副作用。
- 仅保留数据库事件表：无需查询接口，但上报人与维修人员无法通过 API 追溯状态变化。

## 后果

接口契约增加事件 DTO，需要两名人工评审。后续 SLA、验收和 M1 写回任务仍按其各自验收标准实现；它们不得绕过状态机与事件事务。

## 验证

M3 数据库集成测试覆盖授权、`DISPATCHED → IN_PROGRESS → DONE`、已有的升级与返工回到维修中、非法状态不新增事件，以及事件历史访问控制。
